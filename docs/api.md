# ReconLens — API (Phase 5)

FastAPI app: `backend/app/api/main.py`. Run with
`uvicorn backend.app.api.main:app --reload` (or via `docker compose up`).
Interactive docs at `/docs` (Swagger UI, auto-generated by FastAPI).

## Endpoints

| Method | Path | Purpose |
|---|---|---|
| POST | `/batches` | Submit ledger + settlement records; runs the full pipeline synchronously and returns the batch summary |
| GET | `/batches/{batch_id}` | Batch status and summary |
| GET | `/batches/{batch_id}/decisions` | All reconciliation decisions in a batch |
| GET | `/decisions/{decision_id}` | Full confidence-card payload for one decision (probability, decision, risk flags, evidence) |
| GET | `/reviews?status=OPEN` | Review queue, optionally filtered by status |
| GET | `/reviews/{review_id}` | Review task detail with evidence snapshot |
| POST | `/reviews/{review_id}/approve` | Human approval - creates a REVIEW_APPROVED audit event, preserves the original ML decision |
| POST | `/reviews/{review_id}/reject` | Human rejection - same preservation guarantee |
| GET | `/exceptions?category=...` | List exceptions, optionally filtered by category |
| GET | `/audit/{entity_type}/{entity_id}` | Full ordered audit history for a batch, decision, or review |

## No LLM agents, no chatbot layer

Per spec section 5: this API is orchestration, persistence, and human
oversight around the existing learned reconciliation engine. No agent
framework, no RAG, no autonomous planning was added - the model is already
the AI here.

## Demo flow (spec section 28), confirmed against real data

1. `POST /batches` with a 50+ record batch -> returns summary with
   high_confidence_matches / needs_review / likely_no_match / structural
   counts (verified: 130 records -> 72 candidates -> 57/1/14 split, 9
   structural matches, in a real run against Postgres)
2. `GET /batches/{batch_id}/decisions` -> list all decisions, find a
   one_to_many one
3. `GET /decisions/{decision_id}` -> shows probability, evidence, relationship
   type, risk flags (real KNOWN_LOW_GENERALIZATION flag on genuine
   one-to-many cases, confirmed)
4. `GET /reviews` -> open review queue
5. `POST /reviews/{review_id}/approve` -> human resolves it
6. `GET /audit/DECISION/{decision_id}` -> full history: MODEL_EVALUATED,
   REVIEW_TASK_CREATED, REVIEW_APPROVED, each a separate immutable event
